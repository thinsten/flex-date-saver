## 5. 测试中发现并已修复的问题

| 问题 | 发现方式 | 修复 |
|---|---|---|
| 本机全局安装的 flyai-cli 1.0.5 没有火车命令 | 阶段 0 核验 | 运行环境固定 1.0.16 |
| 并发和高频调用触发频控与风控 | 阶段 0 至阶段 4 | 跨进程限流：QPS ≤2，请求间隔随机 2.5–4 秒，每分钟 ≤20 次，每 10 分钟 ≤40 次；一旦被风控，所有进程一起冷却 20 分钟；30 分钟内相同查询走缓存 |
| 服务端航班缓存忽略时段参数，导致「偶发无航班」 | 阶段 3 对比实测 | 航班查询不再带时段参数，时刻在本地过滤 |
| 往返查询在正式 Key 下返回空 | 阶段 0 | 往返价改为两段单程相加 |
| 火车座席参数不生效，返回里有硬座慢车 | 阶段 0 | 按返回的座席在本地过滤 |
| 酒店区域关键词不生效，品牌字段不可靠 | 阶段 0 | 行政区作为目的地参数；商圈按名称和地址过滤；按名称里的品牌词识别连锁 |
| 衔接不上的日期组合仍去查火车，浪费调用次数 | B6 第 1 次运行 | Skill 1.1 增加航班预检 |
| 某日接口返回空时，同类日期被一并跳过 | 本机 L2 | 当日无数据单独标记，不计入同类失败 |
| 智能体回复里出现内部字段名和「T?」占位符 | B1 | 提示词禁止，智能体更新到第 2 版 |
| 部署：zip 要先通过文件审核；与官方 Skill 同名会被拒；更新智能体要带版本号 | 首次部署 | `tools/deploy_bailian.py` 已适配 |

## 6. 已知限制

- **飞猪行为风控**：安全团队不公开规则。加白前实测同一个 Key 当天被封多次后，冷却时间会越来越长（约 8 分钟 → 14 分钟 → 超过 38 分钟）。2026-10-15 16:46 起 Key 已加白，只限 QPS ≤2 连续 60 次无风控。不同百炼会话在不同沙箱里，限流状态不共享，多个会话同时查价时合计 QPS 可能超过 2。
- **查询预算**：单次规划最多调用 40 次（加白前为 20 次）。时间窗口较宽时只能覆盖部分日期组合，结果中会明确提示。
- **数据边界**：火车不返回余票；酒店价格是每晚参考起价；2027 年假期安排为预估；价格以飞猪预订页为准。
